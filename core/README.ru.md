# core — верификационный примитив totp-presence

Ядро проекта. Делает одну вещь: отвечает на вопрос «это правильный
6-значный TOTP-код от владельца?». Ответ — да или нет.

Всё остальное — окна сессий, хуки, интеграции с конкретными
агентскими системами — живёт **вне ядра**, в `examples/`.

## Состав

```
core/
├── setup.sh         — установщик ядра (запускается через sudo)
├── verify.sh        — верификатор
└── README.ru.md     — этот файл
```

После установки (`sudo ./core/setup.sh install`) на диске появляется:

```
/etc/totp-presence/
├── secret           root:wheel 600 — секретный ключ (base32)
└── verify           root:wheel 755 — верификатор

/etc/sudoers.d/totp-presence        root:wheel 440 — sudo без пароля для verify
```

Три артефакта под root. Всё.

При работе также может появиться `/etc/totp-presence/fail-counter`
(root:wheel 644) — счётчик неудачных попыток для защиты от перебора.
Создаётся автоматически, сбрасывается при успешной проверке.

## Публичный API

### `sudo /etc/totp-presence/verify <код>`

Чистая проверка. Читает секретный ключ, сверяет 6-значный код
(HMAC-SHA1, RFC 6238), возвращает код завершения:

- `0` — код верный
- `2` — код неверный
- `3` — заблокирован: слишком много подряд неверных попыток
- `1` — ошибка (пустой ввод, нет ключа, нет python3, неверный путь
  `--session` и т.п.)

Вывод: при успехе — `ok` на stdout. При ошибке — сообщение на
**stderr** (не stdout). Это важно для скриптования: stdout чист при
любом исходе кроме успеха.

**Защита от перебора.** После 5 подряд неверных кодов верификатор
блокируется на 5 минут. Успешная проверка сбрасывает счётчик.
Параллельные вызовы сериализуются через эксклюзивную блокировку
(atomic mkdir), так что параллельный атакующий не обходит счётчик.

### `sudo /etc/totp-presence/verify <код> --session <путь>`

То же самое, но при верном коде **дополнительно** записывает текущую
метку времени (unix timestamp) в указанный файл. Путь жёстко
валидируется:

- должен быть внутри `/etc/totp-presence/`
- должен быть прямым потомком каталога (без подкаталогов)
- без `..`, без `//`

После записи файл получает права `root:wheel 644`.

Это единственный способ для интеграций безопасно хранить сессию.
Путь и имя выбирает интеграция:

```sh
sudo /etc/totp-presence/verify 123456 \
     --session /etc/totp-presence/claude-code-session
```

## Что ядро НЕ делает

- Не знает про окна сессии и их длительность.
- Не знает про конкретные агентские системы и их интерфейсы.
- Не редактирует пользовательские конфигурации
  (`~/.claude/settings.json` и т.п.).
- Не предоставляет команду «проверить, открыта ли сессия» — это
  делает интеграция, читая свой файл сессии и сравнивая метку
  времени с текущим моментом.

Если кажется, что ядро должно что-то из этого уметь — скорее всего,
это логика интеграции, и ей место в `examples/`.

## Проверка после установки

```sh
# 1. Чистая проверка — только да/нет, ничего не меняет
sudo /etc/totp-presence/verify 123456   # подставь свежий код
echo $?                                  # 0 = верный, 2 = неверный

# 2. Проверка + сессия — записывает метку времени в файл
sudo /etc/totp-presence/verify 123456 \
     --session /etc/totp-presence/test-session
ls -l /etc/totp-presence/test-session    # root:wheel 644
cat /etc/totp-presence/test-session      # unix timestamp

# чистим
sudo rm /etc/totp-presence/test-session
```

## Как написать свою интеграцию

Минимум:

1. Выбрать имя файла сессии внутри `/etc/totp-presence/`, например
   `my-integration-session`.
2. При каждой точке проверки читать этот файл и сравнивать метку
   времени с текущим временем минус длительность окна.
3. Когда сессия просрочена — выдать пользователю или агенту
   инструкцию выполнить:
   ```sh
   sudo /etc/totp-presence/verify <код> --session /etc/totp-presence/my-integration-session
   ```
4. Всё. Ядро сделает остальное.

Реальный пример — [../examples/claude-code-hook/](../examples/claude-code-hook/).

## Почему так мало

Меньше кода — меньше поверхность аудита. Меньше состояния — меньше
способов ошибиться. Ядро делает одно, делает это хорошо, остальное —
дело интеграции.
