# soft-prompt — инструкции для агента + MCP-инструменты

Связка из двух слоёв: текстовые инструкции в промпте говорят агенту
**когда** проверять идентичность собеседника, MCP-инструменты из
[mcp-server](../mcp-server/) дают **чем** проверять. Агент сам
решает когда нужна верификация и сам вызывает инструменты.

## Когда это подходит

- Как дополнение к `claude-code-hook` — агент заранее проверяет
  сессию в ситуациях, которые hook не покрывает (инструменты только
  для чтения, последовательности безобидных действий).
- Для агентов в мягком режиме — без жёсткой блокировки, но с
  осознанной проверкой идентичности.

## Установка

1. Установить ядро: `sudo ./core/setup.sh install`
2. Установить интеграцию для файлов сессии:
   `sudo ./examples/claude-code-hook/install.sh` (или собственную)
3. Подключить MCP-сервер — см.
   [mcp-server/README.ru.md](../mcp-server/README.ru.md)
4. Открыть [prompt.ru.md](./prompt.ru.md), заменить `<integration>`
   на имя интеграции (например, `claude-code`)
5. Скопировать блок в системный промпт или CLAUDE.md агента

## Что агент будет делать

С этим промптом и MCP-инструментами агент:

- Перед чувствительными действиями вызывает `totp_check_session` —
  проверяет, открыта ли сессия.
- Если нет — просит у владельца код и вызывает `totp_verify`.
- Владелец видит, зачем агент просит код, и решает, давать или нет.
- При сомнении в идентичности — проверяет заранее.

## Сравнение режимов

| | Только hook | soft-prompt + MCP | hook + soft-prompt + MCP |
|---|---|---|---|
| Инъекция не может обойти | да | нет* | да |
| Агент понимает зачем | нет | да | да |
| Агент проверяет заранее | нет | да | да |
| Работает без поддержки hooks | нет | да | — |

\* Инъекция может заставить агента не вызывать инструменты проверки,
но не может произвести валидный TOTP-код.

**Рекомендация:** комбинировать все три слоя. Hook блокирует на
уровне операционной системы (инъекция не обойдёт). Soft-prompt даёт
понимание (агент знает зачем и когда). MCP даёт инструменты.

## Адаптация

**Другое имя интеграции:** заменить `<integration>` в prompt.ru.md на
имя своей интеграции. Имя = префикс файлов в `/etc/totp-presence/`
(например, `aider` → `aider-session`, `aider-config`).

**Другие триггеры:** список «когда проверять» в prompt.ru.md —
отправная точка. Если агент работает только с кодом и не имеет
доступа к SSH или графическому интерфейсу — соответствующие пункты
можно убрать.

## Агенты без терминала (Telegram, Slack и др.)

В мягком режиме (только soft-prompt + MCP, без hook) агент
свободно вызывает инструменты обмена сообщениями и может попросить
код через канал связи — проблем нет.

В жёстком режиме (с hook) инструмент обмена сообщениями должен быть
разрешён без сессии — иначе агент не сможет попросить код.
Подробности — в
[claude-code-hook/README.ru.md](../claude-code-hook/README.ru.md),
раздел «Каналы связи».

**Адаптация промпта:** человек не видит терминал — все инструкции
агента должны идти через канал связи. Формулировки в prompt.ru.md
должны подходить для используемого канала.
