# soft-prompt — инструкции для агента + MCP-тулы

Связка из двух слоёв: текстовые инструкции в промпте говорят агенту
**когда** проверять идентичность собеседника, MCP-тулы из
[mcp-server](../mcp-server/) дают **чем** проверять. Вместе они
образуют active mode: агент сам решает когда нужна верификация и
сам вызывает соответствующие тулы.

## Как это работает

```
 prompt (текст)           MCP-сервер (тулы)
 ┌─────────────────┐     ┌──────────────────────┐
 │ "перед опасным   │     │ totp_check_session() │
 │  действием       │ ──► │ totp_verify()        │
 │  проверь сессию" │     │ totp_status()        │
 └─────────────────┘     └──────────────────────┘
         КОГДА                    ЧЕМ
```

Prompt даёт агенту **понимание** — зачем нужна проверка и в каких
ситуациях. MCP-тулы дают **инструменты** — структурированные
вызовы с JSON-ответами.

## Когда это подходит

- Агентская система не поддерживает `PreToolUse`-хуки, но
  поддерживает MCP (Claude Desktop, Cursor, Continue).
- Как дополнение к `claude-code-hook` — агент проактивно
  запрашивает код в ситуациях, которые hook не покрывает
  (тулы в exit-list, последовательности безобидных действий).
- Для агентов, работающих в «мягком» режиме — без жёсткой
  блокировки, но с осознанной проверкой идентичности.

## Установка

1. Установи ядро: `sudo ./core/setup.sh install`
2. Установи интеграцию для session-файлов:
   `sudo ./examples/claude-code-hook/install.sh` (или создай свою)
3. Подключи MCP-сервер — см. [mcp-server/README.ru.md](../mcp-server/README.ru.md)
4. Открой [prompt.md](./prompt.md), замени `<integration>` на имя
   интеграции (например `claude-code`)
5. Скопируй блок в system prompt или CLAUDE.md агента

## Что агент будет делать

С этим промптом + MCP-тулами агент:

- Перед чувствительными действиями вызывает `totp_check_session` —
  проверяет, открыта ли сессия.
- Если нет — просит у владельца код и вызывает `totp_verify`.
- Владелец видит зачем агент просит код и решает, давать или нет.
- При сомнении в идентичности — проверяет проактивно, не дожидаясь
  deny от хука.

## Сравнение с hook-only и MCP-only

| | Hook only | Soft-prompt + MCP | Hook + soft-prompt + MCP |
|---|---|---|---|
| Injection не может обойти | да | нет* | да |
| Агент понимает зачем | нет | да | да |
| Агент проактивно проверяет | нет | да | да |
| Работает без hook-поддержки | нет | да | — |

\* Injection может заставить агента не вызывать MCP-тулы, но не может
произвести валидный TOTP-код. Подробнее — в prompt.md, секция "Границы".

**Рекомендация:** комбинируй все три слоя. Hook даёт enforcement
(injection не может обойти). Soft-prompt даёт понимание (агент знает
зачем и когда). MCP даёт инструменты (структурированные тулы вместо
shell-команд).

## Адаптация

**Другое имя интеграции:** замени `<integration>` в prompt.md на
имя своей интеграции. Имя = префикс файлов в `/etc/totp-presence/`
(например `aider` → `aider-session`, `aider-config`).

**Другие триггеры:** список "когда проверять" в prompt.md — отправная
точка. Адаптируй под свой use case: если агент работает только с
кодом и не имеет доступа к SSH, секция про VPN/GUI избыточна.

**Без MCP:** если MCP недоступен, агент может использовать
shell-команды напрямую:
```sh
# Проверить сессию
cat /etc/totp-presence/<integration>-session
# Открыть сессию
sudo /etc/totp-presence/verify <код> --session /etc/totp-presence/<integration>-session
```
Это менее удобно (нет структурированного JSON-ответа), но работает.
