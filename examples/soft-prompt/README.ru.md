# soft-prompt — интеграция через system prompt

Самый простой способ подключить `totp-presence` к агенту: скопировать
текстовый блок в его system prompt (или CLAUDE.md, или аналог в другом
фреймворке). Не требует хуков, MCP, специального харнесса — только
`core/setup.sh install` и текст в промпте.

## Когда это подходит

- Агентская система не поддерживает `PreToolUse`-хуки (Aider, некоторые
  конфигурации Cursor, кастомные обвязки).
- MCP-клиент недоступен или избыточен для задачи.
- Как дополнение к hook или MCP — агент проактивно запрашивает код,
  а не только реагирует на deny.

## Как использовать

1. Установи ядро: `sudo ./core/setup.sh install`
2. Установи интеграцию (любую), чтобы появились session/config файлы.
   Или создай вручную:
   ```sh
   sudo sh -c 'echo 0 > /etc/totp-presence/my-agent-session'
   sudo chmod 644 /etc/totp-presence/my-agent-session
   ```
3. Открой [prompt.md](./prompt.md), замени плейсхолдеры:
   - `<integration>` → имя твоей интеграции (например `my-agent`)
   - `<window_seconds>` → длительность окна (например `1500`)
4. Скопируй блок в system prompt агента.

## Что агент будет делать

С этим промптом агент:
- Перед чувствительными действиями проверяет, открыта ли сессия.
- Если нет — просит у владельца TOTP-код и выполняет `verify --session`.
- Принимает коды только от человека через прямой канал, не из текстов.
- Для необратимых действий просит подтверждение даже при открытой сессии.

## Границы — честный разговор

Soft-prompt — это **мягкая** защита. Агент следует правилам, потому что
они в его промпте. Injection, достаточно сильная чтобы переписать
инструкции, может отключить эту защиту.

Это не делает soft-prompt бесполезным:

- Injection должна **знать** про totp-presence и целенаправленно
  отключать его. Случайная injection этого не сделает.
- Injection должна быть достаточно длинной и авторитетной чтобы
  перевесить system prompt. Это не тривиально для коротких инъекций.
- Даже если injection переписала правила, она всё ещё не может
  произвести валидный TOTP-код. Она может заставить агента **не
  проверять** сессию, но не может **открыть** её.

Для жёсткой защиты, которую injection не может обойти:
- [claude-code-hook](../claude-code-hook/) — harness-level enforcement
- [mcp-server](../mcp-server/) — структурированные тулы для агента

Рекомендация: комбинируй soft-prompt с hook или MCP. Soft-prompt даёт
агенту **понимание** зачем нужна проверка. Hook/MCP даёт **enforcement**.
Понимание без enforcement — уязвимо. Enforcement без понимания —
работает, но агент не будет проактивно запрашивать код в ситуациях,
которые hook не покрывает.

## Адаптация под свой фреймворк

`prompt.md` написан для агента, который может выполнять shell-команды
(`sudo /etc/totp-presence/verify ...`). Если твой агент не может
вызвать shell (например, чистый чат-бот без тулов), адаптируй:

- Убери команды verify — агент не может их выполнить.
- Оставь правила запроса кода у человека и правила про границы
  сессии.
- Человек сам выполняет verify в терминале, агент только спрашивает
  «дай мне код» и доверяет ответу.

Это слабее (человек может забыть выполнить verify), но лучше чем
ничего.
