# claude-code-hook — интеграция для Claude Code

Блокировка инструментов в Claude Code через `PreToolUse`-хук.
Защищённые инструменты не вызываются, пока владелец не открыл
сессию валидным TOTP-кодом.

## Что устанавливается

Три файла, все принадлежат root:

```
/etc/totp-presence/claude-code-guard.sh     root:wheel 755 — хук
/etc/totp-presence/claude-code-session      root:wheel 644 — метка времени сессии
/etc/totp-presence/claude-code-config       root:wheel 644 — настройки интеграции
```

Своего sudoers-правила интеграция не добавляет — использует
правило ядра для `verify`.

## Установка

Ядро должно быть установлено заранее:

```sh
sudo ./core/setup.sh install
```

Потом интеграция:

```sh
sudo ./examples/claude-code-hook/install.sh
# или с другим окном сессии:
sudo ./examples/claude-code-hook/install.sh --window-minutes 15
# для агентов без терминала (Telegram и др.):
sudo ./examples/claude-code-hook/install.sh --messaging-tools "mcp__plugin_telegram_telegram__reply"
```

Установщик:

1. Копирует `guard.sh` в `/etc/totp-presence/claude-code-guard.sh`.
2. Создаёт `claude-code-session` с нулевой меткой (сессия сразу
   просрочена).
3. Пишет `claude-code-config` с `WINDOW_SECONDS` и опционально
   `EXTRA_SAFE_TOOLS`. При переустановке сохраняет существующие
   значения `EXTRA_SAFE_TOOLS` и `EDIT_WRITE_CONFIG_ONLY`, если
   они не заданы явно через флаги.
4. Печатает JSON-сниппет для `~/.claude/settings.json`. Его нужно
   добавить вручную — Claude Code попросит явное подтверждение.

> **Порядок первого запуска.** Если используется полная блокировка
> (matcher `.*`), MCP-сервер totp-presence должен быть подключён
> и загружен **до** добавления хука. Иначе агент не сможет вызвать
> `totp_verify` для открытия сессии. Порядок: добавить MCP-сервер
> в конфиг → перезапустить Claude Code → убедиться что
> MCP-инструменты появились → добавить хук.

## Как агент открывает сессию

Когда агент вызывает защищённый инструмент, а сессия просрочена,
хук возвращает отказ с точной командой. Агент просит код у владельца
и выполняет:

```sh
sudo /etc/totp-presence/verify 123456 --session /etc/totp-presence/claude-code-session
```

Ядро проверяет код и записывает метку времени в файл сессии. Хук
при следующем вызове увидит свежую сессию и пропустит инструмент.

## Два режима блокировки

### Полная блокировка (matcher `.*`)

Каждый вызов инструмента приходит в хук. Хук пропускает без
проверки короткий список безопасных инструментов:

```
Read | Glob | Grep | LS | TodoWrite | WebSearch | mcp__totp-presence__*
```

Всё остальное требует открытой сессии:

- `Bash` (shell-команды)
- `Write`, `Edit`, `NotebookEdit` (изменение файлов)
- `WebFetch` (может попасть на action-URL)
- `Task` / `Agent` (подагенты, которые сами вызывают инструменты)
- Любые другие MCP-инструменты

**Почему перечислены безопасные, а не опасные.** Обычный подход —
перечислить опасные инструменты — даёт уязвимость: всё, что забыли
перечислить, или что появится в обновлении, или что добавит новый
плагин — не защищено. Здесь наоборот: новые инструменты
автоматически попадают под защиту.

MCP-инструменты `totp-presence` (`mcp__totp-presence__*`) встроены
в список безопасных — иначе агент не сможет вызвать `totp_verify`
чтобы открыть сессию. Это безопасно: `totp_verify` проходит через
ядро с защитой от перебора, `totp_check_session` и `totp_status` —
чистое чтение.

### Выборочная блокировка (selective matcher)

Вместо `.*` можно указать конкретные инструменты в matcher:

```json
{
  "matcher": "Bash|Edit|Write|mcp__peekaboo__.*|mcp__computer-use__.*"
}
```

Только перечисленные инструменты проходят через хук, остальные
работают свободно. Гибче, но новые инструменты не защищены
автоматически.

При выборочной блокировке можно дополнительно включить опцию
`EDIT_WRITE_CONFIG_ONLY=true` в конфигурации интеграции. С ней
Edit и Write на обычные файлы проходят без проверки сессии, а
конфигурационные файлы (`settings.json`, `settings.local.json`,
`.claude.json`, `CLAUDE.md`, `.claude/agents/*`) по-прежнему
требуют укороченное окно (120 секунд). Bash-команды с упоминанием
конфигурационных путей тоже блокируются. Без этой опции (по
умолчанию) Edit и Write требуют сессию как любой другой инструмент.

## Каналы связи (EXTRA_SAFE_TOOLS)

Если агент общается с человеком через внешний канал (Telegram,
Slack), messaging-инструмент нужно разрешить без сессии — иначе
агент не сможет попросить код. Задаётся при установке:

```sh
sudo ./examples/claude-code-hook/install.sh --messaging-tools "mcp__plugin_telegram_telegram__reply"
```

Или вручную в `/etc/totp-presence/claude-code-config` (sudo):

```
EXTRA_SAFE_TOOLS=mcp__plugin_telegram_telegram__reply
```

Несколько инструментов через `|`.

При выборочной блокировке `EXTRA_SAFE_TOOLS` обычно не нужен —
messaging-инструмент просто не попадает в matcher.

## Защита конфигурационных файлов

Помимо обычного окна сессии (25 мин), хук применяет укороченное
окно (120 секунд) для файлов, контролирующих безопасность агента:

- `settings.json`, `settings.local.json` — настройки хуков
- `.claude.json` — конфигурация MCP-серверов
- `CLAUDE.md` — инструкции агенту
- `.claude/agents/*` — определения агентов

Укороченное окно применяется к трём инструментам:

- **Edit и Write** — по `file_path` в параметрах вызова.
- **Bash** — хук парсит содержимое shell-команды и проверяет
  текстовым поиском наличие конфигурационных путей. Прямые команды
  (`echo >> settings.json`, `sed -i CLAUDE.md`) ловятся.
  Обфускация (переменные, base64, eval) не ловится — для этого
  нужна защита на уровне файловой системы (см.
  [SECURITY_MODEL.ru.md](../../SECURITY_MODEL.ru.md), §5b).

Зачем отдельное окно, а не полная блокировка: бывает легитимная
потребность изменить настройки через агента. Человек просит агента
поменять конфиг → агент запрашивает свежий код → человек видит
зачем и решает → код открывает 2-минутное окно для правки.

## Особенности работы без терминала (headless)

В headless-режиме (Telegram, Slack) встроенный approve-диалог
Claude Code не является надёжной проверкой: человек видит только
«Permission: Edit / Allowed» без содержимого правки. TOTP-запрос
перед правкой конфигурации служит дополнительным подтверждением —
человек видит, что агент собирается менять настройки, и решает,
давать ли код.

## Удаление

```sh
sudo ./examples/claude-code-hook/install.sh uninstall
```

Удаляет три файла интеграции. Ядро остаётся — его можно удалить
отдельно через `sudo ./core/setup.sh uninstall`.

Запись хука из `~/.claude/settings.json` установщик не трогает —
напечатает `jq`-команду для ручного удаления.

## Что закрывает и что нет

**Закрывает:** вызов инструментов без свежего TOTP-кода. Подделку
файла сессии (root-owned). Подмену хука (root-owned).

**Не закрывает:** выполнение кода в обход системы инструментов.
Инъекцию, убеждающую владельца дать код под предлогом безобидной
задачи (переиспользование сессии в открытом окне).

Полный разбор — [SECURITY_MODEL.ru.md](../../SECURITY_MODEL.ru.md).
