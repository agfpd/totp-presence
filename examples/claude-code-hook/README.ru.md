# claude-code-hook — интеграция для Claude Code

Блокировка инструментов в Claude Code через `PreToolUse`-hook.
Защищённые инструменты не вызываются, пока владелец не открыл
сессию валидным TOTP-кодом.

## Что устанавливается

Два статических файла под root, плюс файл сессии, создаваемый по
требованию при первом успешном TOTP-коде:

```
/etc/totp-presence/claude-code-guard.sh                  root:wheel 755 — hook
/etc/totp-presence/claude-code-config                    root:wheel 644 — настройки интеграции

/var/run/totp-presence/<user>/claude-code-session        root:wheel 644 — метка времени сессии
                                                                          (создаётся по требованию,
                                                                          очищается при перезагрузке)
```

Файл сессии живёт во временном дереве по пользователям (tmpfs на
Linux, синтетическая ФС на macOS) и потому временный по дизайну:
перезагрузка машины очищает любые сессии, и пользователь должен
заново аутентифицироваться.

Своего правила sudoers интеграция не добавляет — использует правило
ядра для `verify`.

## Установка

Ядро должно быть установлено заранее:

```sh
sudo ./core/setup.sh install
```

Потом интеграция:

```sh
sudo ./examples/claude-code-hook/install.sh
# или с другим окном сессии:
sudo ./examples/claude-code-hook/install.sh --window-minutes 15
# для агентов без терминала (Telegram и др.):
sudo ./examples/claude-code-hook/install.sh --messaging-tools "mcp__plugin_telegram_telegram__reply|mcp__plugin_telegram_telegram__react|mcp__plugin_telegram_telegram__edit_message|mcp__plugin_telegram_telegram__download_attachment"
# явная полная блокировка (рекомендуется при свежей установке с `matcher: ".*"`):
sudo ./examples/claude-code-hook/install.sh --full-lockdown
# явная выборочная блокировка (в паре с узким `matcher`):
sudo ./examples/claude-code-hook/install.sh --selective-edit-write
```

Установщик:

1. Копирует `guard.sh` в `/etc/totp-presence/claude-code-guard.sh`.
2. Пишет `claude-code-config` с `WINDOW_SECONDS` и опционально
   `EXTRA_SAFE_TOOLS` и `EDIT_WRITE_CONFIG_ONLY`. При повторной
   установке `EXTRA_SAFE_TOOLS` из существующей конфигурации
   сохраняется тихо, если не переопределён флагом.
   `EDIT_WRITE_CONFIG_ONLY` тоже сохраняется, но если унаследованное
   значение — `true`, печатается предупреждение, потому что этот
   режим критичен для безопасности (пропускает Edit/Write на
   неконфигурационные файлы без сессии), и тихое наследование при
   повторной установке — грабли. Передай `--full-lockdown` чтобы
   принудительно выключить, или `--selective-edit-write` чтобы
   принудительно включить и заглушить предупреждение.
3. Если обнаружен файл сессии в старой схеме v1
   (`/etc/totp-presence/claude-code-session`), он переезжает в новое
   расположение по пользователям, а старый файл удаляется. Сессии и
   счётчик переборов больше не хранятся под `/etc/totp-presence/`.
4. НЕ создаёт файл сессии заранее — верификатор создаёт его по
   требованию при первом успешном TOTP-коде по адресу
   `/var/run/totp-presence/<пользователь>/claude-code-session`. Hook
   трактует отсутствующий файл сессии как «сессия никогда не
   открывалась» (отказ).
5. Печатает JSON-фрагмент для `~/.claude/settings.json`. Его нужно
   добавить вручную — Claude Code попросит явное подтверждение.

> **Порядок первого запуска.** Если используется полная блокировка
> (`matcher: ".*"`), MCP-сервер totp-presence должен быть подключён
> и загружен **до** добавления hook. Иначе агент не сможет вызвать
> `totp_verify` для открытия сессии. Порядок: добавить MCP-сервер в
> конфигурацию → перезапустить Claude Code → убедиться, что
> MCP-инструменты появились → добавить hook.

## Как агент открывает сессию

Когда агент вызывает защищённый инструмент, а сессия просрочена,
hook возвращает отказ с точной командой. Агент просит код у
владельца и выполняет:

```sh
sudo /etc/totp-presence/verify 123456 --session /var/run/totp-presence/$USER/claude-code-session
```

Ядро проверяет код и записывает метку времени в файл сессии
(создавая директорию пользователя при первом использовании). Hook
при следующем вызове увидит свежую сессию и пропустит инструмент.

## Два режима блокировки

### Полная блокировка (`matcher: ".*"`)

Каждый вызов инструмента приходит в hook. Hook пропускает без
проверки короткий список безопасных инструментов:

```
Read | Glob | Grep | LS | TodoWrite | WebSearch | ToolSearch | mcp__totp-presence__*
```

Всё остальное требует открытой сессии:

- `Bash` (команды оболочки)
- `Write`, `Edit`, `NotebookEdit` (изменение файлов)
- `WebFetch` (может попасть на действующий URL)
- `Task` / `Agent` (подагенты, которые сами вызывают инструменты)
- Любые другие MCP-инструменты

Почему список перевёрнут (перечислены безопасные, а не опасные) и
почему MCP-инструменты totp-presence встроены в него — см.
[SECURITY_MODEL.ru.md, §4](../../SECURITY_MODEL.ru.md#4-список-безопасных-инструментов-должен-оставаться-узким).

### Выборочная блокировка (узкий `matcher`)

Вместо `.*` можно указать конкретные инструменты в `matcher`:

```json
{
  "matcher": "Bash|Edit|Write|mcp__peekaboo__.*|mcp__computer-use__.*"
}
```

Только перечисленные инструменты проходят через hook, остальные
работают свободно. Гибче, но новые инструменты не защищены
автоматически.

При выборочной блокировке можно дополнительно включить опцию
`EDIT_WRITE_CONFIG_ONLY=true` в конфигурации интеграции. С ней
Edit и Write на обычные файлы проходят без проверки сессии, а
конфигурационные файлы (`settings.json`, `settings.local.json`,
`.claude.json`, `CLAUDE.md`, `.claude/agents/*`) по-прежнему
требуют укороченное окно (120 секунд). Команды Bash с упоминанием
конфигурационных путей тоже блокируются. Без этой опции (по
умолчанию) Edit и Write требуют сессию как любой другой инструмент.

Режим задаётся явно через установщик:

```sh
# включить (выборочная блокировка):
sudo ./examples/claude-code-hook/install.sh --selective-edit-write
# выключить (полная блокировка):
sudo ./examples/claude-code-hook/install.sh --full-lockdown
```

Эти два флага конфликтуют и не могут быть переданы вместе. Без
любого из флагов существующее значение сохраняется при повторной
установке, и если унаследованное значение — `true`, установщик
печатает предупреждение, потому что эта комбинация бесшумно
пропускает Edit/Write на неконфигурационные файлы, и её легко
забыть после смены `matcher` в `settings.json`.

## Каналы связи (EXTRA_SAFE_TOOLS)

Если агент общается с человеком через внешний канал (Telegram,
Slack), инструмент обмена сообщениями нужно разрешить без сессии —
иначе агент не сможет попросить код. Задаётся при установке:

```sh
sudo ./examples/claude-code-hook/install.sh --messaging-tools "mcp__plugin_telegram_telegram__reply|mcp__plugin_telegram_telegram__react|mcp__plugin_telegram_telegram__edit_message|mcp__plugin_telegram_telegram__download_attachment"
```

Или вручную в `/etc/totp-presence/claude-code-config` (sudo):

```
EXTRA_SAFE_TOOLS=mcp__plugin_telegram_telegram__reply|mcp__plugin_telegram_telegram__react|mcp__plugin_telegram_telegram__edit_message|mcp__plugin_telegram_telegram__download_attachment
```

Несколько инструментов через `|`. Каждое имя должно соответствовать
`[a-zA-Z0-9_]+`. Hook перепроверяет значение при загрузке:
повреждённый `EXTRA_SAFE_TOOLS` (метасимволы регулярного выражения
вроде `.*` или любые символы вне этого набора) отвергается с одной
строкой в стандартном потоке ошибок, вызов уходит в обычную
сессионную проверку — вместо тихого пропуска всех инструментов через
более широкое регулярное выражение.

При выборочной блокировке `EXTRA_SAFE_TOOLS` обычно не нужен —
инструмент обмена сообщениями просто не попадает под `matcher`.

## Защита конфигурационных файлов

Помимо обычного окна сессии (25 мин), hook применяет укороченное
120-секундное окно для файлов, контролирующих безопасность агента:
`settings.json`, `settings.local.json`, `.claude.json`, `CLAUDE.md`,
`.claude/agents/*`. Edit и Write сопоставляются по `file_path`;
команды Bash сканируются по тем же путям, причём диагностические
команды чтения (`cat`, `grep`, `jq`, …) проходят без сессии.

Полные правила классификатора, ограничения по обфускации и
обоснование укороченного окна вместо полной блокировки —
[SECURITY_MODEL.ru.md, §5b](../../SECURITY_MODEL.ru.md#5b-модификация-конфигурации-агента-через-shell-команды).

## Особенности работы без терминала

В режиме без терминала (Telegram, Slack) встроенный диалог
подтверждения Claude Code не является надёжной проверкой: человек
видит только «Permission: Edit / Allowed» без содержимого правки.
Запрос TOTP-кода перед правкой конфигурации служит дополнительным
подтверждением — человек видит, что агент собирается менять
настройки, и решает, давать ли код.

## Удаление

```sh
sudo ./examples/claude-code-hook/install.sh uninstall
```

Удаляет статические файлы интеграции (`claude-code-guard.sh`,
`claude-code-config`) и любые файлы сессии по пользователям под
`/var/run/totp-presence/<пользователь>/claude-code-session`. Если
найден файл сессии в старой схеме v1 под `/etc/totp-presence/` —
он тоже удаляется. Ядро остаётся — его можно удалить отдельно через
`sudo ./core/setup.sh uninstall`.

Запись hook из `~/.claude/settings.json` установщик не трогает —
напечатает команду `jq` для ручного удаления.

## Что закрывает и что нет

**Закрывает:** вызов инструментов без свежего TOTP-кода. Подделку
файла сессии (принадлежит root). Подмену hook (принадлежит root).

**Не закрывает:** выполнение кода в обход системы инструментов.
Инъекцию, убеждающую владельца дать код под предлогом безобидной
задачи (переиспользование сессии в открытом окне).

Полный разбор — [SECURITY_MODEL.ru.md](../../SECURITY_MODEL.ru.md).
